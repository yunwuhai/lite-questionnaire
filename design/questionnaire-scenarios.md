# Questionnaire 交互场景模拟

本文档用文字描述用户操作和插件响应，覆盖 14 个普通和边界场景，用于验证交互设计是否正确。

---

## 场景 1：单问题单选（最简场景）

> 问卷：1 个问题，"选语言" [TypeScript, Python, Rust]

```
界面显示：
┌─────────────────────────────────────────┐
│ ◯ Q1                                1/1 │
│                                         │
│ 选语言 [必填]                           │
│                                         │
│   1. TypeScript                         │
│ > 2. Python                             │  ← 光标在此
│   3. Rust                               │
│   4. 自定义                             │
│                                         │
│ Space 选择 · ↑↓ 移动 · Enter 提交 · Esc 取消 │
└─────────────────────────────────────────┘
```

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 按 `↓` 到选项 1 | 光标移到 TypeScript |
| 2 | 按 `Space` | Python 被标定（显示 `•` 高亮符号），进度点变绿 |
| 3 | 按 `Enter` | 提交，返回结果 `{ lang: "py", label: "Python" }` |

## 场景 2：单问题多选

> 问卷：1 个问题，"选语言" [TS, Python, Rust]，maxSelect: 3

```
界面显示：
┌─────────────────────────────────────────┐
│ ◯ Q1                                1/1 │
│                                         │
│ 选语言 [必填]                           │
│                                         │
│ > [ ] 1. TypeScript                     │

│   [ ] 3. Rust                           │
│   [ ] 4. 自定义                         │
│                                         │
│ Space 切换 · ↑↓ 移动 · Enter 提交 · Esc 取消 │
└─────────────────────────────────────────┘
```

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | `↓` 到选项 1，`Space` | `[x] TypeScript`，进度点变绿 |
| 2 | `↓` 到选项 3，`Space` | `[x] Rust` |
| 3 | `Enter` | 提交，返回 `{ lang: ["ts", "rs"] }` |

## 场景 3：多选 + 自定义（正常流程）

> 同上问卷

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | `Space` 勾选 TypeScript | `[x] TypeScript` |
| 2 | `↓` 到"自定义"，`Space` | `[x] 自定义`（勾选但内容为空） |
| 3 | `Tab` | 进入编辑模式，光标在输入框 |
| 4 | 输入 "Go" | 显示 `> Go█` |
| 5 | `Enter` | 保存编辑，返回选项列表，显示 `[x] 4. "Go"` |
| 6 | `Enter` | 提交，返回 `{ lang: ["ts", "Go"], wasCustom: true }` |

---

## 场景 4：自定义编辑但不勾选（边界）

> 同上问卷

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | `↓` 到"自定义" | 光标在"自定义"上 |
| 2 | `Tab`（未先 Space 勾选） | 进入编辑模式 |
| 3 | 输入 "Zig"，`Enter` | 保存编辑内容，返回选项列表 |
| 4 | `Enter` | 提交——**自定义内容被丢弃** |

**关键行为**：编辑内容临时保留在内存中。如果用户在步骤 4 之前 `←` 回来再 `Space` 勾选它，之前输入的 "Zig" 还在。但只有勾选 + 编辑的内容才会被提交。

## 场景 5：Enter 跳过未答题（红色进度点）

> 问卷：3 个问题（Q1 语言 / Q2 框架 / Q3 数据库）
> 初始进度点：◯ ◯ ◯

| 步骤 | 用户操作 | 当前题 | 进度点变化 | 说明 |
|------|---------|--------|-----------|------|
| 1 | 在 Q1 什么都不选，直接 `Enter` | → Q2 | 🔴 ◯ ◯ | Q1 红色：进入过但未答 |
| 2 | 在 Q2 `Space` 选一项，`Enter` | → Q3 | 🔴 🟢 ◯ | Q2 绿色：已回答 |
| 3 | 在 Q3 `Space` 选一项，`Enter` | → 提交页 | 🔴 🟢 🟢 | Q3 绿色 |

提交页显示：
```
┌─────────────────────────────────────────┐
│ ✓ 提交                           3/3+1  │
│                                         │
│ 确认你的选择：                          │
│                                         │
│ ⚠ Q1 语言: (未回答)                    │
│ ✓ Q2 框架: 3. React                    │
│ ✓ Q3 数据库: 1. PostgreSQL             │
│                                         │
│ ⚠ 以下问题未完成，无法提交：Q1          │
│ ← 回到问题修改                          │
└─────────────────────────────────────────┘
```

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 4 | 按 `Enter` | **无响应**（Q1 未完成，禁止提交） |
| 5 | 按 `←` 回到 Q1 | 进度点保持 🔴🟢🟢，进入 Q1 |
| 6 | `Space` 选一项，`Enter` | 进度点变 🟢🟢🟢，跳到 Q2 |
| 7 | `→` 到提交页 | 全部绿色，可以提交 |
| 8 | `Enter` | 提交成功 |

---

## 场景 6：← 回退修改

> 用户已答完 Q1 → Q2 → Q3，进度点全绿 🟢 🟢 🟢

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | `←` 回到 Q2 | Q2 之前的选择恢复显示（草稿保留），进度点保持 🟢 |
| 2 | `Space` 切换选中项 | 选项更新，进度点仍是 🟢 |
| 3 | `Enter` | 重新提交 Q2，进度点保持 🟢，前进到 Q3 |

---

## 场景 7：条件子问题（分步插入）

> 问卷：Q1 "选语言" → 如果选 TS，插入子问题 Q1.1 "选框架"
> 初始 Tab 序列：Q1 ｜ Q2（数据库）｜ Submit

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | Q1 `Space` 选 TypeScript，`Enter` | Tab 序列变为：**Q1 ｜ Q1.1(框架) ｜ Q2(数据库) ｜ Submit** |
| 2 | 进度点：🟢 Q1  ◯ Q1.1  ◯ Q2 |
| 3 | Q1.1 `Space` 选 React，`Enter` | 进度点：🟢 Q1  🟢 Q1.1  ◯ Q2，前进到 Q2 |

**如果 Q1 选 Python（无子问题）**：
| 1 | Q1 `Space` 选 Python，`Enter` | Tab 序列不变，直接跳到 Q2 |

## 场景 8：text 类型问题

> 问卷：Q1 "项目描述"（text 类型）

```
界面显示：
┌─────────────────────────────────────────┐
│ ◯ Q1                                1/1 │
│                                         │
│ 项目描述 [必填]                         │
│                                         │
│ 你的回答：                              │
│ > █                                     │  ← 进入即编辑，无选项列表
│                                         │
│ Enter 提交 · Esc 取消                   │
└─────────────────────────────────────────┘
```

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 输入 "一个高性能 API 服务" | 编辑器中显示文本 |
| 2 | `Enter` | 提交，返回 `{ description: "一个高性能API服务" }` |

**边界**：如果用户什么都不输入按 `Enter`，且该题为 required → 校验失败，显示"请输入内容"，不前进。

## 场景 11：约束校验

> 多选题 "选语言"，约束 `minSelect: 2, maxSelect: 3`

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 只勾选 1 项，`Enter` | 底部显示：`⚠ 至少选择 2 项`，不前进 |
| 2 | 补充勾选到 2 项，`Enter` | 通过，前进 |
| 3 | 尝试勾选第 4 项 | `Space` 无效果（已达 maxSelect=3）或显示 `⚠ 最多选择 3 项` |

## 场景 12：Esc 取消

| 场景 | 用户操作 | 系统响应 |
|------|---------|---------|
| 普通选项中 | 按 `Esc` | 直接取消，返回 `"User cancelled the questionnaire"` |
| 编辑模式中（自定义） | 按 `Esc` | 丢弃编辑内容，返回选项列表 |
| 编辑模式中（text 类型） | 按 `Esc` | 取消整个问卷 |

---

## 场景 13：会话持久化

| 步骤 | 事件 | 系统响应 |
|------|------|---------|
| 1 | 用户答到第 3 题（共 5 题） | 当前状态在内存中 |
| 2 | 用户关闭终端（或 pi 重启） | 状态自动序列化到会话文件 |
| 3 | 用户重新打开 pi，触发同一问卷 | 从会话文件恢复状态 |
| 4 | 界面恢复 | 从第 3 题开始，之前答案保留，进度点：🟢 Q1  🟢 Q2  ◯ Q3  ◯ Q4  ◯ Q5 |

## 场景 14：约束校验在提交页

> Q1 未答（红色进度点），Q2 已答，Q3 已答

```
提交页显示：
┌─────────────────────────────────────────┐
│ ✓ 提交                           3/3+1  │
│                                         │
│ 确认你的选择：                          │
│                                         │
│ ⚠ 语言: (未回答)                       │
│ ✓ 框架: 1. React                       │
│ ✓ 数据库: 2. PostgreSQL                 │
│                                         │
│ ⚠ 未完成: 语言 → 无法提交               │
│ ← 回到问题修改                          │
└─────────────────────────────────────────┘
```

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 按 `Enter` | **无响应**（Q1 未完成，禁止提交） |
| 2 | 按 `←` 回到 Q1 | 进入 Q1 |
| 3 | `Space` 选一项，`Enter` | Q1 变绿，前进 |
| 4 | `→` 回到提交页 | 全部绿色 |
| 5 | `Enter` | 提交成功 |
